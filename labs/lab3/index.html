    Отчёт по лабораторной работе №3

    Тема: CI/CD для статического сайта в SourceCraft и GitHub Actions

    Цель работы

    Получить практические навыки настройки CI/CD для автоматической сборки и публикации статического сайта, созданного с помощью MkDocs. Настроить автоматическое развертывание одного локального проекта одновременно на SourceCraft и GitHub Pages.

    1. Используемые технологии

    В ходе выполнения лабораторной работы использовались:

    • Git --- система контроля версий;
    • GitHub --- удалённый Git-репозиторий и платформа для запуска GitHub Actions;
    • GitHub Actions --- средство автоматизации сборки и развертывания сайта;
    • GitHub Pages --- хостинг статического сайта;
    • SourceCraft --- платформа для хранения репозитория и автоматического развертывания статического сайта;
    • MkDocs --- генератор статических сайтов на основе Markdown;
    • Material for MkDocs --- тема оформления сайта.

    2. Организация репозитория

    Для лабораторной работы используется один локальный Git-репозиторий. Он связан сразу с двумя удалёнными репозиториями:

    • origin --- репозиторий на GitHub;
    • sourcecraft --- репозиторий на SourceCraft.

    Проверить подключённые удалённые репозитории можно командой:

    git remote -v

    Отправка изменений в GitHub выполняется командой:

    git push origin main

    Отправка тех же изменений в SourceCraft выполняется командой:

    git push sourcecraft main

    Таким образом, исходный код сайта хранится в двух удалённых репозиториях, а развертывание выполняется независимо средствами GitHub и SourceCraft.

    Структура проекта

    Основные файлы и каталоги проекта организованы следующим образом:

    p4vel11.github.io/
├── .github/
│   └── workflows/
│       └── actions.yaml
├── src/
│   ├── docs/
│   │   └── ...
│   └── mkdocs.yml
├── requirements.txt
└── README.md

    Назначение основных элементов:

    • .github/workflows/actions.yaml --- сценарий CI/CD для GitHub Actions;
    • src/mkdocs.yml --- конфигурационный файл MkDocs;
    • src/docs/ --- Markdown-файлы и другие материалы статического сайта;
    • requirements.txt --- Python-зависимости, необходимые для сборки сайта;
    • README.md --- описание проекта.

    В requirements.txt указаны необходимые зависимости:

    mkdocs
mkdocs-material

    В конфигурации mkdocs.yml используется тема Material:

    theme:
  name: material

    3. Выполненные действия

    3.1. Создание сайта на MkDocs

    Была подготовлена структура статического сайта на MkDocs. Страницы сайта размещены в каталоге src/docs, а настройки сайта находятся в файле src/mkdocs.yml.

    Для проверки проекта локально можно установить зависимости:

    pip install -r requirements.txt

    После этого сайт можно собрать командой:

    mkdocs build -f src/mkdocs.yml

    Для запуска локального сервера разработки используется:

    mkdocs serve -f src/mkdocs.yml

    4. Настройка GitHub и GitHub Actions

    Для хранения проекта был использован публичный репозиторий:

    p4vel11/p4vel11.github.io

    Для автоматического развертывания сайта был настроен GitHub Actions.

    Workflow расположен по пути:

    .github/workflows/actions.yaml

    Он запускается автоматически после отправки изменений в ветку main.

    Пример используемой конфигурации:

    name: Deploy MkDocs Site

on:
  push:
    branches:
      - main
  workflow_dispatch:

permissions:
  contents: write

jobs:
  build:
    name: Deploy docs
    runs-on: ubuntu-latest

    steps:
      - name: Checkout main
        uses: actions/checkout@v4

      - name: Deploy docs
        uses: mhausenblas/mkdocs-deploy-gh-pages@master
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
          CONFIG_FILE: src/mkdocs.yml
          REQUIREMENTS: requirements.txt

    Workflow выполняет следующие действия:

    1. запускается после push в ветку main;
    2. получает содержимое репозитория;
    3. устанавливает зависимости проекта;
    4. собирает сайт с помощью MkDocs;
    5. публикует результат в ветку gh-pages;
    6. GitHub Pages использует содержимое ветки gh-pages для публикации сайта.

    4.1. Настройки репозитория GitHub

    Для корректной работы автоматического деплоя в настройках GitHub были выполнены следующие действия.

    В разделе:

    Settings → Actions → General → Workflow permissions

    было установлено:

    Read and write permissions

    Это необходимо для того, чтобы GITHUB_TOKEN, используемый workflow, мог записывать результат сборки в ветку gh-pages.

    Также в разделе:

    Settings → Pages

    был выбран способ публикации:

    Source: Deploy from a branch
Branch: gh-pages
Folder: / (root)

    После выполнения workflow GitHub Pages публикует собранный статический сайт.

    Так как репозиторий называется p4vel11.github.io, сайт доступен по адресу:

    https://p4vel11.github.io/

    5. Настройка SourceCraft

    Для выполнения второй части развертывания была использована платформа SourceCraft.

    Были выполнены следующие действия:

    1. выполнена авторизация в SourceCraft с помощью аккаунта Яндекс;
    2. создана публичная организация;
    3. создан публичный пустой репозиторий;
    4. создан персональный токен доступа (PAT) для работы с Git по HTTPS;
    5. токену были предоставлены права Maintainer;
    6. репозиторий SourceCraft был добавлен в локальный проект как дополнительный remote;
    7. исходный код проекта был отправлен в SourceCraft;
    8. для проекта было настроено автоматическое развертывание статического сайта.

    Дополнительный remote добавляется командой:

    git remote add sourcecraft https://<имя_аккаунта>:<персональный_токен>@git.sourcecraft.dev/<имя_аккаунта>/<имя_репозитория>.git

    После добавления выполняется проверка:

    git remote -v

    В результате локальный проект содержит два удалённых репозитория:

    origin       -> GitHub
sourcecraft  -> SourceCraft

    Первичная отправка ветки main в SourceCraft выполняется командой:

    git push sourcecraft main

    Персональный токен является секретными данными, поэтому его значение не должно добавляться в исходный код, отчёт или публичный Git-репозиторий.

    5.1. Настройки SourceCraft

    Непосредственно на стороне SourceCraft для реализации деплоя необходимо:

    • создать публичную организацию и репозиторий;
    • предоставить токену необходимые права для отправки изменений в репозиторий;
    • настроить CI/CD-сценарий проекта для сборки MkDocs;
    • указать команды установки зависимостей и сборки сайта;
    • в качестве результата сборки использовать каталог со сгенерированным статическим сайтом;
    • включить публикацию сайта средствами SourceCraft Sites;
    • убедиться, что pipeline успешно выполняется после отправки изменений в ветку main.

    При каждом новом push в SourceCraft запускается CI/CD-сценарий, MkDocs генерирует статические HTML-файлы, после чего они публикуются на SourceCraft Sites.

    Итоговый адрес имеет формат:

    https://<username>.sourcecraft.site/<repo_name>/

    6. Процесс автоматического деплоя

    После внесения изменений в документацию выполняются команды:

    git add .
git commit -m "Update site"
git push origin main
git push sourcecraft main

    После git push origin main автоматически запускается GitHub Actions. Он собирает MkDocs-сайт и публикует его через GitHub Pages.

    После git push sourcecraft main запускается CI/CD-сценарий SourceCraft, который также собирает проект и публикует сайт через SourceCraft Sites.

    Таким образом, один локальный проект автоматически развертывается на двух независимых платформах.

    7. Результат работы

    В результате выполнения лабораторной работы:

    • создан статический сайт на MkDocs;
    • настроен единый локальный Git-репозиторий;
    • к локальному репозиторию подключены GitHub и SourceCraft;
    • настроена автоматическая сборка сайта;
    • настроен деплой через GitHub Actions;
    • настроена публикация через GitHub Pages;
    • настроен CI/CD и публикация сайта через SourceCraft;
    • один и тот же проект может публиковаться на двух хостингах после отправки изменений в соответствующие удалённые репозитории.

    8. Вывод

    В ходе лабораторной работы был изучен процесс CI/CD для статического сайта на MkDocs. Был настроен один локальный репозиторий с двумя удалёнными репозиториями --- GitHub и SourceCraft.

    Для GitHub автоматическая сборка и публикация выполняются с помощью GitHub Actions и GitHub Pages. Для SourceCraft используется встроенный CI/CD-механизм и сервис публикации статических сайтов.

    В результате изменения сайта можно отправлять в соответствующий удалённый репозиторий, после чего сборка и развертывание выполняются автоматически без необходимости вручную создавать и загружать HTML-файлы.
